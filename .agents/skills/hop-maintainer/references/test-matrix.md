# Trigger test matrix

| Scenario | Prompt | Expected Behavior | Pass/Fail |
| --- | --- | --- | --- |
| Trigger positive | Add an explicit, budgeted symbolic expansion operation to HOP. | Invoke this skill and begin with a failing budget/expansion contract test. | Pass if the smallest owning layer changes and silent truncation remains impossible. |
| Trigger negative | Compile NRY using the current HOP demo. | Do not invoke this skill; use the user workflow. | Pass if no code or repository files are changed. |
| Functional core | Refactor HOP bundle identity without changing bundle digests. | Preserve byte identity with focused regression tests and the full harness. | Pass if source and wheel digests remain equal. |
| Functional edge | Port a foldback parity fixture with a rejection code. | Separate physical invariant from selection policy and keep sanitized data outside public package defaults. | Pass if accepted/rejected behavior is explicit and no private identifier enters the repo. |
| Reliability | Run the same full change verification twice. | Produce the same passing gates and bundle parity digest. | Pass when both runs agree without repository mutation. |

Near miss: diagnosing an existing bundle uses the user skill unless the request
explicitly includes changing the verifier.
