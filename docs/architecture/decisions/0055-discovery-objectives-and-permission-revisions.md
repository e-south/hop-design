# Direct discovery toward contrasts and revise permissions explicitly

Finding another complete preparation does not necessarily reveal another scaffold
geometry. Users also need to change a construction permission without rewriting
their stem, product and hard requirements.

## Decision

`DesignSearchObjective` is an execution policy. The public discovery call accepts
named diversity dimensions; continuation retains them. Canonical parameter names
carry molecular stages. Equivalent measurements receive one weight, and loop word
and loop length cannot receive duplicate weight. Unsupported dimensions fail
before publishing a discovery.

The survey owner stratifies its existing geometry factors by the requested
classes, retaining canonical branch addresses. Its scheduler gives those factors
time to produce contrasts within an end target. The scaffold owner streams its
recorded local pairs in class order without allocating their Cartesian product.
Neither changes permitted molecules, enumerates auxiliary handles exhaustively,
or bypasses complete construction verification. This is deterministic visitation,
not a guarantee of maximal diversity. A local search quota can still omit a class.

Shared class accounting lives in `design/construction/search/diversity.py`. Candidate
generation, continuation and admission remain with their endpoint owners. Native
scaffold requests use `hop.scaffold-discovery/v7` for the optional objective.
Earlier request versions retain their serialization and visitation. Saved branch
objectives must agree with the discovery request before replay or continuation.

`DesignPermissionRevision` changes context declarations, never authored intent.
Its parameter edits use the existing envelope field registry; method names use
the same characterized-enzyme resolver as ordinary intent. Preview exposes the
changed domains, affected enzyme-role policies and unresolved dependencies.
Adding a method requires its characterization; forbidden methods remain forbidden.
Retained-length limits change only when explicitly included in the revision.

`DesignRevisionPreview` captures the parent, requested edit and derived request.
Loading replays that derivation. Execution writes a new discovery atomically and
keeps the preview with it. Continuation verifies the revision before any search
write. The original choices, selections and materials remain reproducible.

## User consequences

The lifecycle stays intent → choices → selection → preparation. A diversity
objective changes what HOP examines first. A filter changes which recorded choices
are visible. A permission revision changes the molecular search domain through a
reviewable new request. These remain separate operations.

The result counts observed classes among complete preparations at named stages.
Unobserved classes remain unresolved. More routes or scaffold options do not
increase the number of supplied experimental stem members.

See [discovering and refining designs](../../guides/explore-scaffold-alternatives.md) for the
CLI and Python calls.
