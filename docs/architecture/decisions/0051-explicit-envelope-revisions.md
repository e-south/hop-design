# Explicit construction envelope revisions

A finite result pool is not the permitted design space. A value absent from that
pool may be unexamined, excluded by another choice, or outside the current request.
Increasing a drawing's trace density must not invent complete constructions.

## Decision

Keep three operations distinct:

1. Query existing complete preparations under the current selections and controls.
2. Evaluate a selected region within the active generating envelope: the
   permissions in the request used for further discovery.
3. Preview an explicit permission revision, then evaluate it with supplied quotas.

`models/construction/variants/envelope.py` owns a field whitelist and strict edit
contract. The discovery request remains the validator for edited values and joint
requirements. Stem, receiving end words/polarity, material policies, whole-route
constraints, catalog and forbidden enzymes cannot be changed through this operation.
Stage-qualified query controls and the fixed reference survive all three operations.
The end-placement roster remains paired; neither independent gap brushing nor
revision fabricates a permitted cross-product. Derived R constrains A/D pairs.

The revision preview captures original query, explicit changes, revised generating
request and targeted evaluation request. It searches no molecules. Evaluation
recomputes the preview, captures the old packet unchanged and adds ordinary bounded
discovery. Admission replays the parent, revision and new results. It retains
previous preparation labels and deduplicates exact preparations. The latest revised
request becomes the generating envelope for subsequent evaluations.

The accumulated pool is historical evidence: a preparation obtained under an earlier
envelope stays inspectable even after permissions narrow. Its original request stays
in `previous/`. The current envelope is authority for **future evaluation**, not a
claim that every historical preparation satisfies newly narrowed permissions. Query
selections and preservation controls explicitly govern current eligibility.

## Domain navigation

`ParameterDomainQuery` pages integer intervals, finite categories and unfixed A/C/G/T
words without enumerating their full Cartesian space. A word domain is navigable by
length and prefix. Pages have at most 64 values; exact cardinalities are decimal
strings in the projection to avoid JavaScript integer rounding. A status reports
complete support, exclusion by current selections, or no complete preparation
recorded. It never upgrades local support or a failed continuation to a universal
feasibility verdict. Branch diagnostics retain their evaluated scope.

Browser, CLI and Python use this projection. A proposed pivot lists the axis
selections that differ in an existing complete preparation; it cannot clear a
preservation control. The browser contains no molecular solver. Full paths denote
recorded preparations; domain ticks denote permissions. Static and interactive
views share state-qualified parameter definitions and bracket boundaries.

## Parameter responsibility

In the foldback measurements below, A is the paired extension from the supplied
stem to the loop, D is the join position measured from that stem boundary, and C
is loop length. R is the self-paired portion from the join to the loop, with
R = A − D.

| Request information | Representation |
| --- | --- |
| Foldback A, D, C, words, strand; derived R | Axes and joint local restriction compiler |
| Basal n, annealing, positional bases/contact classes | Axes; local restrictions and complete-route checks |
| End words, polarity and joint gaps | Stage-qualified axes; words/polarity locked during revision |
| Whole-hairpin geometry and chemistry | Achieved axes; declared scaffold requirements stay locked |
| Method roles | Named categorical axes; catalog and prohibitions retained |
| Recognition patterns and cut offsets | Derived enzyme annotations, never independent knobs |
| Supplied stem, exact material policies, preservation | Fixed requirements or explicitly stage-qualified query controls |
| Retained construction and search quotas | Generating/evaluation bounds, separately labeled from dimensions |

## Verification

Unit checks cover open domains, joint R targets, unknown/locked edits, invalid
values and allocation-bounded paging. Integration checks cover preview conflicts,
CLI parity, revision replay, relocated retrieval and unchanged earlier evidence.
Browser checks cover explicit pivots, preserved controls, unobserved choices and
live preview/evaluation through the same API. The full repository gate includes
installed-wheel parity. The public example's computational quota is not a molecular
minimum, completeness guarantee, or performance claim for arbitrary requests.
