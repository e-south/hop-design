# Terminal scaffold specification and stage-qualified comparisons

Let users specify terminal hairpin architecture, discover complete alternatives,
and retrieve preparations without manually translating shape into adapter and
annealing settings. Existing request meanings and sealed evidence remain intact.

## Delivery checklist

- [x] Exact/ranged terminal counts; shared achieved-state authority; permitted
  translation; preview, complete discovery, selection and portable retrieval.
- [x] Stage-qualified regional controls with set/group scope, nucleotide ancestry,
  explicit unassessed correspondence and unchanged legacy controls.
- [x] Required-member-directed discovery, deterministic shared budgets, reused
  overlapping work and complete coverage reporting without domain relaxation.
- [x] Verified prior-material bindings compiled to fixed policies; explicit
  distinction from product preservation and sharing among new members.
- [x] Generated molecular comparison sheets: requested/achieved termini, intended
  differences, shared controls, prior-material changes, missing members, retrieval.
- [x] Public CLI/API dogfooding, repeated execution, relocation, altered-reference
  rejection, publication-size visual review and installed-wheel parity.
- [x] Strict preflight, full verification and requirement-by-requirement closure.

## Acceptance cases

The terminal example must obtain 6/14, 6/8, 6/0 and 0/0 unpaired 5-prime/3-prime
nucleotides through high-level requirements. The fully paired example adds six
open-side paired positions; only the adapter changes in this demonstrated set.
Counts do not define arbitrary new sequence or establish assembly compatibility.

Stage controls must admit the appropriate eight-preparation loop-by-method
released-product comparison while preserving hairpin differences. An unintended
retained-region change must reject. Required TTC must be examined before optional
AAA under the demonstrated tight quota, with incomplete domain coverage explicit.
Preserving a prior insert may change its source; fixing that prior source may not.

HOP owns contracts and reusable rendering. Caller studies own questions and
dogfood evidence. Manuscript selection, new chemistry, experimental qualification,
and public publication remain outside this implementation.

## Execution and verification

Use test-first increments and keep modules within repository structure limits.
Each delivery includes its public example, documentation and rendered output.
Run focused tests during development, then `bash scripts/agent-preflight --strict`
and `bash scripts/agent-verify`. Record actual evidence here as work completes;
partial verification cannot close the delivery checklist.
