# Product-first scaffold discovery

The user specifies a scaffold and intended product, explores permitted
preparations, compares changes at the relevant molecular stage and retrieves
explicitly named members. This extends the [complete-options workflow](scaffold-options.md)
without changing its inner molecular evaluator.

## Scope and ownership

HOP owns strict authoring, bounded branch expansion, complete evaluation,
request-bound replay, stage comparisons and portable reports. Caller-owned
studies own use-case interpretation and experimental observations. No new
chemistry, exposed-end hairpin capability, automatic repair, performance ranking,
laboratory-stock inference or manuscript composition belongs in this increment.

The live worktree, including pre-existing changes, is the implementation base.
Existing single-request exploration and selection remain available and retain
their molecular requirements. All public examples use existing public inputs.

## Contract and dependency direction

`models.construction.discovery` owns the strict outer request. The
`design.construction.discovery` package intersects declared hard requirements,
expands explicit permissions, delegates ordinary complete-options evaluation and
replays every branch before selection. Export consumes projected facts and
existing molecular drawings; it does not infer chemistry or feasibility.

Adapter settings are preparation candidates. For the supported forward-source
route, the nick-to-stem span contributes open-side positions, and proximal
pairing can impose a larger span than the annealing minimum. The complete
achieved-state check remains authoritative. A fixed adapter is never replaced
by an implicit derived one. More search budget cannot resolve contradictory
declarations.

Keep product identity separate from construction and material identity. Intended
endpoint and comparison stage are separate declarations. An intermediate
hairpin may differ even when released strands, interfaces and chemistry agree.
The report groups exact products separately from preparation alternatives and
uses aligned whole molecules, a changed-region enlargement and material-role differences.

## Verification and handoff

Every behavioral increment starts with an observed failing public-seam test.
Validate strict bounds, fixed-material preservation, requirement intersections,
branch identity, incomplete coverage, semantic replay, explicit membership and
create-only output. Run the repository's strict preflight and full verification
before declaring the complete increment delivered. Public source and installed
wheel must execute the same request, discovery and retrieval example.

Dogfood records must retain authored requests, producer, bounds, branch outcomes,
selected identities, manual edits and observed interpretation errors. Preserve
the original failed request beside an explicitly edited alternative. Review
rendered SVG/PDF output for stage clarity, readable dimensions and no invented
completed molecule for a failed preparation.
